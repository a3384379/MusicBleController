# Android 历史同步与分页

Android Controller 从 Sony 同步播放历史和统计，Room 保存本地副本。历史请求独立于歌曲歌词、封面传输；切歌不会取消历史分包或其响应期限。Sony 仍是历史数据的权威来源，BLE 命令、响应及分包格式沿用现有协议。

## 核心实现

- `PlaybackHistoryCoordinator`：单消费者处理请求、分包、数据库提交和列表窗口；入口锁及不可变操作代次保护并发失效。
- `ControllerRepository`：保留原动作入口，将历史通知和写入失败转交协调器；通知进入媒体队列前捕获历史代次。
- `PlaybackHistoryDatabase`：本地历史、持久游标、事务和 v1 升级。
- `ControllerViewModel` / `ControllerCommandGateway`：历史动作及返回最近记录入口。
- `ControllerAppUi`：固定状态面板、有界历史列表及稳定行标识。
- `PlaybackHistoryCoordinatorTest`：虚拟时钟下的确定性状态和期限回归。
- `ControllerHistoryRegressionTest`：真实 Room、分包、请求隔离、迁移、事务回滚和数据量边界。
- `ControllerUiSmokeTest`：实际 Compose 导航、滚动锚点、固定反馈和返回最近。

## 请求生命周期

历史协调器统一管理增量同步、加载更早记录、统计队列和分包。每次响应需要匹配当前请求的 requestId、响应类型和统计范围。本地操作代次隔离清理、断线和重新连接前的响应，以及已排队的异步解析和数据库提交。

发送失败、写入失败、无效分包、解码失败、数据库失败及响应超时都必须结束对应请求。统计范围失败后继续剩余范围，最终保留部分失败的反馈。每个请求保留 8 秒响应期限；重复分包不能无限延长请求寿命。

清理和历史提交由同一个串行边界协调。清理开始时使旧操作代次失效，数据库事务同时清空历史与游标；清理结束后，旧响应不能重新写回记录。新的主动同步可以重新取得 Sony 数据。关闭或断线结束当前请求，保留已提交的本地历史。

## 增量与向前分页

增量同步使用 afterSessionId；读取更早历史使用 beforeSessionId。两种游标分别维护，均不能从当前可见的 500 条记录推断。

更早分页优先消费 Sony 已有的 nextBeforeSessionId。旧响应缺少该字段时，只能从本次有效响应推导。hasMore 为 true 时游标必须推进，否则结束操作并允许重试。历史记录和对应持久游标在同一个 Room 事务中提交。

Sony 会返回尚未结束的播放会话，同一 sessionId 后续还可能更新收听时长、完播结果和结束时间。单轮增量分页可以向前推进；持久化水位需要保证下轮仍会重读未结束会话，不能把尚未完成的最大 ID 当成最终完成水位。

列表首次读取 500 条，本地追加和远端分页共用最多 1000 条的可见窗口。同步新增记录时保留原窗口底部；新增量超过预算时冻结原阅读范围，并提供返回最近记录入口。返回最近重新读取 500 条并滚到列表顶部。窗口位置与远端游标分别管理；状态、进度和重试区域固定在列表上方，阅读旧记录时仍可见。

若远端页全部命中缓存，仍按真实响应推进持久游标，每次点击最多发一个分页请求，并提示已经检查缓存、可以继续读取更早记录。终页结束加载；不会为了跳过重叠页而自动发起无界请求。

## 数据库升级和回退

数据库 v2 增加 history_cursor 表。MIGRATION_1_2 保留 v1 的 playback_history 表及全部记录。旧库没有可靠的增量完成水位，因此从零开始重新确认；既有记录通过主键合并，不因迁移而删除。

正常打开数据库使用显式迁移，移除破坏性迁移兜底。迁移测试必须从真实 v1 表结构开始，经 Room 打开 v2 后校验记录和游标。

旧 v1 APK 自身包含 fallbackToDestructiveMigration，直接覆盖安装回退可能清空 v2 库。回退构建应继续支持 v2 schema 和迁移，仅回退业务实现；不能将新版本的无损升级测试理解为旧 APK 降级安全。

## 回归验收

| 范围 | 必须验证的行为 |
|---|---|
| 切歌 | 历史分包继续完成，期限与加载状态有确定收尾 |
| 请求隔离 | 错误 requestId、类型、范围及旧代次不能提交数据或推进新请求 |
| 失败恢复 | 缺包、坏 JSON、发送失败、超时和数据库失败后可重新操作 |
| 清理 | 旧直接响应、旧分包及已排队提交不能在清理后回填 |
| 统计 | 一个范围失败后其余范围继续，保留部分失败反馈 |
| 分页 | 0、1、499、500、501、1000、10000 条边界，游标推进且更早记录可读 |
| 重启 | 已提交游标恢复，未结束会话的最终结果可重新同步 |
| 迁移 | v1 记录保持数量和字段，旧记录不会被错误用作完成水位 |
| 界面 | 同步、分页、失败和离线状态可见，列表位置及回到最近入口可用 |

开发验证运行 ControllerApp JVM 单测、Debug APK 构建、lint 和设备端测试。Room 与假传输回归可以在 Android 模拟器执行；Sony 真机 BLE 分包、断线恢复和双控制器验证独立记录。基础构建通过不能代替真实链路验收。

## 本批验证结果

2026 年 11 月 6 日，ControllerApp 的 44 项 JVM 测试通过，包含新增的 10 项历史协调器测试。Android 模拟器全量 48 项设备端测试通过，其中历史回归 42 项、既有协议回归 3 项、Compose UI 回归 3 项。Debug APK 和测试 APK 构建通过；lint 为 0 错误、18 警告。

真实数据库验证了 v1 完整字段保留、游标写入触发 SQLite ABORT 后历史行一起回滚、重试提交成功，以及 JSON 空封面标识保持数据库 NULL。分页边界覆盖 0、1、499、500、501、1000、10000 条；Compose 实际操作验证阅读第 510 条时同步新记录后该行仍可见，并可返回第 1020 条所在的最近窗口。
