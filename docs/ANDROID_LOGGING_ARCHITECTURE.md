# Android 控制端日志

`ControllerLogStore` 负责 Android Controller 的本地诊断日志。生产者提交有界数据，磁盘操作由单个后台任务串行处理；分享入口导出独立快照，避免接收方读到正在轮转的文件。Sony 日志和 iOS `AppLogStore` 不属于此模块。

## 容量与保留

| 对象 | 当前预算 |
|---|---|
| 本地日志 | 每文件 4 MiB，当前文件加三份历史文件，总计最多 16 MiB |
| 待写数据 | 512 KiB，包含正在写入的批次 |
| 批次临时缓冲 | 最多 64 KiB，不跨清理、导出或关闭操作 |
| 入队保护 | 队列达到 2048 项后拒绝日志；控制操作另受 16 项上限，关闭有独立保留位置 |
| 单条输入 | 最多约 8192 个 UTF-16 码元，超长内容带截断标记 |
| 导出副本 | 最多四份，每份最多 16 MiB，独立保存在应用 cache |

预算是内部工程配置，不是 BLE 字段。生产者在向 Handler 投递任务前完成容量检查。`appendImportant` 可挤出尚未写入的普通日志；重要日志或在途批次占满预算时，新消息仍可能被拒绝。当前调用点明确标记问题、连接变化及自愈事件，不通过文案猜测全部错误。

普通日志使用一个 350 毫秒延迟排空任务。连续追加不延长已排队任务，Handler 不按消息数量积累闭包。排空按相邻日志合并批次，写入后释放待写预算；原消息字节与拼接缓冲分别计算。旧版本的超大日志首次访问时收缩到最近可保留的完整行。

## 操作顺序与失败

[BoundedLogCore](../ControllerApp/src/main/java/com/example/controllerapp/data/BoundedLogCore.kt) 统一拥有写入、轮转、清理、导出和关闭。已接受的控制操作是队列屏障：之前的日志先处理，之后的日志不能越过它。清理成功后，同一后台边界再清空诊断页近期列表，避免旧监听回调把已清理内容重新放回界面。

目录、打开、写入、flush、close、移动、删除和快照读取异常均隔离。失败日志不无限保存在内存，也不递归记录到同一服务；后续新写入可再次尝试，并在恢复时记录失写和丢弃汇总。汇总不重放已丢失正文。失败尚未恢复时拒绝导出，以免把不完整结果当作成功快照。

监听器由排空线程按日志顺序在锁外调用，单个监听器抛错不阻断其他监听器。监听器同步追加的消息可以落盘，但不会再次触发通知递归。回调应保持短小，不等待日志线程完成。

`close()` 立即拒绝新提交，排空已接受操作后停止线程；重复调用安全。`awaitClosed(timeoutMs)` 同时确认排空完成与线程退出，不能在日志线程内等待自身。`closeSucceeded()` 在完成前为 null，最后仍有未报告失写或调度失败时为 false；成功不意味着从未丢弃过消息，也不承诺断电后数据持久性。

## 分享与清理

导出在同一后台队列中，按旧到新的顺序复制保留日志，并通过回调返回独立文件。之后追加或轮转不修改已交付快照；ViewModel 将结果送回主线程，用户点击分享后才打开系统选择器。导出失败、服务繁忙和清理失败均有界面反馈。

达到四份副本后，用户可选择“删除已导出的日志副本”。确认框说明尚在读取的分享可能失败；该操作不删除当前本地日志。cache 也可能被系统回收，因此导出副本不作为长期存档。

## 验证与维护

JVM 回归使用真实临时文件和可控制的排空调度，覆盖预算、在途写入、重要消息优先、轮转、旧大文件、写入次数、故障注入与恢复、清理屏障、快照不可变、拒绝调度及重复关闭。设备测试使用真实 HandlerThread 检查监听器隔离、清理和导出顺序及线程实际退出；旧测试不再反射私有线程。

```sh
bash ./gradlew :ControllerApp:testDebugUnitTest :ControllerApp:assembleDebug :ControllerApp:lintDebug
python3 tools/ci/android_device.py controller-history --serial <测试设备> --artifacts <新目录>
```

具体执行结果见[优化进度](OPTIMIZATION_PROGRESS.md)。这些检查验证可靠性和容量，不直接换算成 CPU 或电量节省；长期负载数据随真机验收另行记录。
